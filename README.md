# Loco (Rust) vs Next.js: proof of concept

An evaluation of [Loco](https://loco.rs) 1.2 ([GitHub](https://github.com/loco-rs/loco)) as a batteries-included framework for starting new apps, compared against Next.js 16.

- **[docs/assessment.md](docs/assessment.md)**: findings, benchmarks, Next.js comparison, recommendation. Start here.
- **[docs/research.md](docs/research.md)**: desk research (docs, GitHub, HN), with sources.
- **[bench/results.txt](bench/results.txt)**: raw benchmark and build-time numbers.

## What's here

| Path | What it is |
|---|---|
| `loco-crm/` | The POC: a small CRM on Loco with auth, companies/contacts/deals/notes, a Tera+HTMX UI, a generated React SPA at `/app`, background jobs, mailers, uploads, a scheduler, AI summaries and drafts, a built-in profiler, and 61 tests |
| `nextjs-twin/` | A minimal Next.js 16 app with the same schema, seed and benchmark endpoints, plus a matching profiler |
| `bench/run.sh` | Side-by-side benchmark: cold start, RSS, req/s, latency |

## Run the Loco app

Requires Rust (`rustup`) and Node with pnpm.

```bash
cd loco-crm && cargo loco db migrate && cargo loco task seed_demo
```

```bash
cd loco-crm/frontend && pnpm install && pnpm run build
```

```bash
cd loco-crm && cargo loco start --all
```

Open http://localhost:5150 and log in as `demo@example.com` / `demo-password`. `--all` runs the web server, queue worker and scheduler in one process. Without the worker, AI summaries stay queued.

Optional:
- `ANTHROPIC_API_KEY=...` makes AI calls use Claude (default model `claude-haiku-5-5`, override with `AI_MODEL`). Without it a labelled mock answers.
- `MAILER_STUB=false` with [Mailpit](https://mailpit.axllent.org) running sends real SMTP to `localhost:1025`, which you can read at :8025.

Tests, lints:

```bash
cd loco-crm && cargo test && cargo clippy --all-targets -- -D warnings
```

## Run the benchmark

```bash
cd loco-crm && cargo build --release
```

```bash
cd nextjs-twin && npm install && npm run build
```

```bash
bench/run.sh 15s 50
```

## Code tour (loco-crm)

| Concern | Files |
|---|---|
| App wiring (storage, DB metric hook, profiler layer, routes, workers) | `src/app.rs` |
| Domain logic and validation (fat models) | `src/models/{companies,contacts,deals,notes}.rs` |
| Server-rendered pages + `CurrentUser` cookie extractor | `src/controllers/web.rs`, `assets/views/**` |
| Generated JSON API (used by the SPA, or a mobile app) | `src/controllers/{companies,contacts,deals,auth}.rs`, `src/dtos/` |
| React SPA (generated by scaffolds) | `frontend/src/` → served at `/app` by `src/controllers/spa.rs` |
| Background jobs | `src/workers/{ai_summarize,deal_won}.rs` |
| Email | `src/mailers/deal.rs` + `src/mailers/deal/*/` |
| CLI tasks + schedule | `src/tasks/{seed_demo,pipeline_digest}.rs`, `scheduler:` in `config/*.yaml` |
| LLM client | `src/llm.rs`, settings in `src/settings.rs` |
| Profiler | `src/profiler.rs`, `src/controllers/devtools.rs`, footer script in `assets/views/layouts/base.html`; UI at `/_profiler` |
| Benchmark endpoints (mirror the Next twin) | `src/controllers/bench.rs` |
| Tests | `tests/` (`tests/support/mod.rs` has fixtures) |

`git log` walks through the build step by step. Commits that fix framework issues explain the issue in their messages. The early commits were split out of one working tree after the fact, so the commits before `d05db54` don't each build on their own.
